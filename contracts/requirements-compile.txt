# COMPILE-side toolchain — pinned, and deliberately separate from requirements.txt.
#
# requirements.txt is the RUNTIME environment (pytest, algokit-utils, py-algorand-sdk). This
# file is the environment that turns contracts/inscription.py into the committed artifacts in
# contracts/out/. They are split because puya tracks Python <= 3.13 while the runtime side has
# no such ceiling, and because a compiler version is a reproducibility input in a way a test
# dependency is not.
#
# These exact versions were previously recorded only as a COMMENT in requirements.txt, under a
# heading describing a venv created by compile_contract.ps1 on one developer's machine at
# %USERPROFILE%\trelyan-build. A commented pin cannot be installed, so CI could not reproduce
# the build even in principle, and nothing detected the toolchain moving. This file makes the
# pin machine-readable so verify_teal_matches_source.py can be run anywhere and mean something.
#
# EXACT pins (==), not floors. puya is a compiler: a different version may emit different but
# equally valid TEAL, and byte-comparison against a committed artifact is only meaningful
# against a fixed compiler. Bumping either line is a deliberate act that regenerates
# contracts/out/ in the same commit, with the regenerated bytecode diffed in review.
puyapy==5.8.1
algorand-python==3.5.0
